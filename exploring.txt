Ghidra Metadata Workflow (Function-Centric)

Purpose
- Repeatable workflow for improving decomp understanding around one function.
- Focus areas: function rename, parameter rename/retype, struct fields, globals, comments.
- Use [function address] as the template placeholder (example format: 0x004192d0).

Scope and style
- Be conservative: prefer comments over speculative renames.
- Be liberal with commenting however, so long as it's factual.
- Rename only when behavior is clearly supported by decompile + callsites.
- For uncertain meanings, keep neutral names and mark "Provisional" in comments.
- Prioritize plate comments for functions; pre-comments for globals/data.

0) Baseline context
- Pull target function:
  ./tools/ghidra_api "function/[function address]/decompile"
- Pull graph context:
  ./tools/ghidra_api "function/[function address]/callers"
  ./tools/ghidra_api "function/[function address]/callees"
- Pull relevant type layouts:
  ./tools/ghidra_api "type/[TypeName]/layout"

1) First-pass understanding
- Identify core behavior of [function address]: input validation, state changes, side-effects.
- Identify repeated constants, branch gates, and sentinel values.
- Note candidate names for:
  - the function itself
  - key callees
  - params and fields
  - globals touched

2) Rename/comment order (recommended)
- Step A: add plate comment on [function address] first.
- Step B: rename obvious callees and add their plate comments.
- Step C: rename globals with clear semantics and add pre-comments.
- Step D: retype/rename params and struct fields.

3) Function rename
- Rename function:
  ./tools/ghidra_api "function/rename" '{"addr":"[function address]","new_name":"[NewName]"}'

4) Function signature updates (IMPORTANT format)
- Signature endpoint expects param keys -> object values:
  ./tools/ghidra_api "function/signature" '{
    "addr":"[function address]",
    "return_type":"[optional return type]",
    "[param_name]":{"new_name":"[new_name]","new_type":"[type]"}
  }'
- Param keys must match current decompile param names exactly.
- If you get "parameter not found", re-open decompile and use current names.

5) Comments
- Function plate comment:
  ./tools/ghidra_api "comment/set" '{"function_addr":"[function address]","kind":"plate","comment":"[2-4 factual lines]"}'
- Data/global pre-comment:
  ./tools/ghidra_api "comment/set" '{"addr":"[data addr]","kind":"pre","comment":"[meaning + lifecycle]"}'

6) Struct field updates
- Normal field update:
  ./tools/ghidra_api "struct/modify_field" '{"struct":"[StructName]","offset":[decimal],"name":"[field_name]","data_type":"[type]","comment":"[optional]"}'
- If field conflict is intentional and user confirmed overwrite:
  ./tools/ghidra_api "struct/modify_field" '{"struct":"[StructName]","offset":[decimal],"name":"[field_name]","data_type":"[type]","comment":"[optional]","confirm":true}'

7) Global/symbol rename
- Rename symbol/data:
  ./tools/ghidra_api "symbol/rename" '{"addr":"[data addr]","new_name":"[global_name]"}'
- Verify:
  ./tools/ghidra_api "data/[data addr]"

8) Verification checklist
- Re-open decompile and confirm name propagation:
  ./tools/ghidra_api "function/[function address]/decompile"
- Confirm all intended signatures applied (header shows new names/types).
- Confirm struct layout fields are visible at intended offsets.
- Confirm renamed globals appear in decompile body.
- Confirm no accidental speculative names remain unmarked.

9) Naming conventions (recommended)
- Gameplay flow: NovaGameplay_[Verb][Object]
- Math/helpers: Math_[Verb]
- Sprite/audio/time subsystems: Sprite_/NovaAudio_/NovaTime_
- Globals: g_[system]_[meaning]
- Unknown but bounded: [topic]_metric_a / [topic]_mode / [topic]_latch + comment "Provisional".

10) Safety rules
- Ask/confirm before destructive/conflicting struct updates (confirm:true).
- Do not mass-rename by guess.
- Prefer adding comments when confidence < high.
- Keep changes incremental; verify after each batch.

Quick command template block
- Decompile target:
  ./tools/ghidra_api "function/[function address]/decompile"
- Rename function:
  ./tools/ghidra_api "function/rename" '{"addr":"[function address]","new_name":"[NewName]"}'
- Signature patch:
  ./tools/ghidra_api "function/signature" '{"addr":"[function address]","[param]":{"new_name":"[name]","new_type":"[type]"}}'
- Plate comment:
  ./tools/ghidra_api "comment/set" '{"function_addr":"[function address]","kind":"plate","comment":"[...]"}'
- Caller/callee context:
  ./tools/ghidra_api "function/[function address]/callers"
  ./tools/ghidra_api "function/[function address]/callees"
- Struct field:
  ./tools/ghidra_api "struct/modify_field" '{"struct":"[Struct]","offset":[n],"name":"[field]","data_type":"[type]"}'
- Global rename:
  ./tools/ghidra_api "symbol/rename" '{"addr":"[data addr]","new_name":"[global]"}'
